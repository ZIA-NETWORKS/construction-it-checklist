# construction-it-checklist
A practical IT checklist for construction companies: job site laptops, connectivity, bid data protection, and backups.
A simple, practical checklist for contractors who want their job site technology to be secure, reliable, and easy to manage. No specialized terminology, no vendor pitch. Just the basics that prevent most problems.

Who this is for

Small and mid-sized construction companies (roughly 10 to 150 employees) with a mix of office staff, field crews, and subcontractors.

1. Devices
[ ] Every laptop, tablet, and phone is listed in an inventory
[ ] Field staff have hardware suited to dust, heat, and rough handling
[ ] Full-disk encryption is turned on for every laptop
[ ] Remote lock and wipe is available for lost devices
[ ] Laptops are set up from one standard template
[ ] Updates run on a schedule, not “when someone remembers”
[ ] A spare device is available for critical roles
2. Job site connectivity
[ ] Each site has a primary internet connection suited to its location
[ ] A backup connection exists (for example, cellular failover)
[ ] Signal is tested before a rural project begins
[ ] Subcontractors and visitors use a separate guest network
[ ] Estimating and accounting systems are never on the guest network
[ ] Plans, RFIs, and daily reports live in cloud tools where possible
3. Accounts and logins
[ ] Everyone has their own account (no shared crew logins)
[ ] Multi-factor authentication is on for email, accounting, cloud storage, and project software
[ ] A password manager is in use, including on phones
[ ] Company email is used for company work, not personal accounts
[ ] Folder access is based on role and reviewed every quarter
4. Protecting bid data
[ ] Bid files are stored in one controlled location
[ ] Only people who need pricing details can see them
[ ] Email filtering is in place for impersonation and dangerous links
[ ] Staff know the rule: verify any bank detail change by phone, using a number you already have on file
[ ] Staff are trained to spot fake invoices and spoofed project emails
5. Backup and recovery
[ ] Backups follow the 3-2-1 rule: three copies, two storage types, one off-site
[ ] The off-site copy is isolated from your main network
[ ] A restore test is run at least every three months, using a real file such as a recent bid
[ ] Recovery targets are written down (how long can you be without email, accounting, and plans?)
[ ] Cloud services are backed up too, not assumed to be safe by default
6. People and process
[ ] An onboarding checklist exists for new hires and seasonal staff
[ ] An offboarding checklist exists: disable email, remove folder access, collect devices, change shared passwords
[ ] A one-page incident sheet lists who to call and in what order
[ ] Someone is accountable for IT, whether an internal coordinator or an outside provider
A simple 30-day plan
Week	Focus	What to do
1	Inventory	List every device, router, and cloud account, and who has access
2	Close big gaps	Turn on MFA, roll out a password manager, confirm encryption
3	Fix backups	Verify what is backed up, and run a restore test
4	Standardize	Create a standard laptop setup, site connectivity checklist, and incident sheet
Common mistakes
Mistake	Better approach
Personal email for company work	Company accounts for everyone
One shared crew login	Individual accounts plus MFA
Skipping updates on site machines	Scheduled patching
Cheapest hardware for everyone	Match hardware to the job
Assuming the cloud is a backup	Separate, tested backups
No offboarding process	A short written checklist
